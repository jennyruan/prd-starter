# PRD-000: <title>

## How to read and edit this PRD
- Each section is its own file, so each section has its own Git history and version number.
- Version **vN** of a section = the Nth commit that changed that section's file. Never rewrite history.
- To roll back one section, restore the old content and commit it. This creates a new version that has the old content:
  `git checkout <commit> -- 06-requirements.md && git commit -m "PRD-000 §6: roll back to v3"`
- Item IDs: G- NG- (§4) · US- (§5) · REQ- (§6) · AC- (§7) · F- (§8) · T- (§12) · Q- (§16) · FB- (§17) · TH- SEC- (§20). Only add new IDs. Never renumber.
- SHALL = required · SHOULD = recommended · MAY = optional · [TBD] = unknown, so STOP and ask a human.
- Sections marked [AUTO] are owned by an agent. The agent commits directly, with the prefix `[auto]`.
- Sections marked (product only) can be deleted in a feature PRD.
- New sections are added at the end with the next number. Never renumber existing sections.

## Comparing with the code
- Tag code and tests with the PRD id and item: `PRD-000/REQ-18` (or `/SEC-n`, `/AC-n`) in a comment, test name or test description.
  - Go: `// PRD-000/REQ-18` above the handler; `func TestPRD000_AC7_ConfirmCard(t *testing.T)` with a `// PRD-000/AC-7` comment.
  - TypeScript: `// PRD-000/REQ-18`; `test("PRD-000/AC-7 confirm card shows source quote", …)`.
- Feature plans (`docs/plans/`) list the requirement IDs they build; every PR description lists them too.
- `prd_tool.py trace <this folder> --repo <repo root> --write` builds §3.4: each requirement as Not started / Code only / Code + tests.
- §9.1 and §9.2 use the exact entity and endpoint names from the code, so the PRD and the code can be compared line by line.

## Reference format
Always point to a section by its name, its version, and the specific part:

`[§6 Requirements@v3#REQ-4](06-requirements.md)` → section 6, version 3, item REQ-4
`[§6 Requirements@v3#6.2](06-requirements.md)`   → section 6, version 3, subsection 6.2
